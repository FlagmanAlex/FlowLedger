# Инструкции для Claude

- Всегда отвечай только на русском языке.
- Явные инструкции пользователя (о стиле работы, коммуникации и т.п.) сохраняй сюда как постоянные
  правила, а не только для текущей сессии.

## Контекст проекта — с чего начинать

Рабочий контекст (архитектура, задачи, план-доки) вынесен из корня в `.claude/`, чтобы не раздувать
корень репозитория и не тащить в каждую сессию закрытые темы. Порядок чтения:

1. `.claude/memory.md` — архитектура, принятые решения, стиль, текущий стек. Читать в начале любой
   содержательной сессии.
2. `.claude/plans/tasks.md` — активные задачи и открытые пункты. Что реально нужно сделать сейчас.
3. `.claude/plans/*.md` — план-доки по темам, ещё не полностью закрытым (контекст решений, на
   которые ссылается tasks.md).
4. `.claude/archive/` — закрытые темы и полностью выполненные задачи. Открывать точечно, только
   если явно нужен исторический контекст — не читать по умолчанию.

## Структура `.claude/`

```
.claude/
├── memory.md                    — архитектура и решения (живой документ)
├── plans/                       — активный контекст
│   ├── tasks.md                 — текущие открытые задачи
│   └── 02-byo-firebase.md       — план BYO-Firebase пивота, ещё не полностью закрыт
│                                   (см. tasks.md пункты 10-12)
└── archive/                     — закрытые темы, не грузить в контекст без необходимости
    ├── plans/
    │   ├── 00-initial-setup.md  — первичный scaffold, выполнено и неактуально
    │   └── 01-firebase-pivot.md — пивот на общий Firestore, выполнено и заменено BYO-Firebase
    └── tasks/
        ├── initial-scaffold.md     — закрытые задачи начального scaffold
        └── byo-firebase-core.md    — закрытые задачи базовой реализации BYO-Firebase
```

(`mobile/.claude/settings.json` — отдельная область, конфиг плагина Expo для mobile-подпроекта,
к этой структуре контекста не относится.)

## Контекст по workspace'ам

У каждого npm workspace — свой короткий `CLAUDE.md` в его корне: `client/CLAUDE.md`,
`mobile/CLAUDE.md`, `shared/CLAUDE.md`, `interfaces/CLAUDE.md`, `control-plane/CLAUDE.md`. Claude
Code подхватывает его автоматически при работе внутри этой директории. Каждый такой файл — не
дубликат `memory.md`/`tasks.md`, а указатель: роль workspace'а в двух-трёх предложениях + ссылка
сюда и в `.claude/plans/tasks.md`, отфильтрованная по тегу этого workspace (`[client]`, `[mobile]`,
`[shared]`, `[interfaces]`, `[control-plane]` — теги проставлены прямо в пунктах `tasks.md`).

При заведении нового workspace — заводи для него такой же `CLAUDE.md` по этому шаблону, а новые
задачи в `tasks.md` сразу помечай тегом (можно несколькими, если фича сквозная).

## Правило поддержания структуры

Когда пункт в `.claude/plans/tasks.md` или план-док в `.claude/plans/` полностью закрыт и больше не
нужен как активный контекст — переноси его (или его закрытые подзадачи) в `.claude/archive/` по той
же структуре: план-доки → `archive/plans/`, закрытые группы задач — новым или дополненным файлом в
`archive/tasks/` по теме. Не удаляй историю — переноси, чтобы её можно было поднять точечно, но по
умолчанию она не читалась и не раздувала контекст. При переносе обновляй перекрёстные ссылки в
переносимом файле и в файлах, которые на него ссылаются (`memory.md`, `tasks.md`, соседние план-доки).
