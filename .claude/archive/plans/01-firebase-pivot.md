# План: пивот на Firebase + продуктовая реализация

Статус: выполнено (см. `tasks.md`). Последующая история модели данных: этот пивот → BYO-Firebase
(`01`→см. `02-byo-firebase.md`, `byo-firebase-core.md`) → возврат к единому проекту с
изоляцией по `userId` (`single-project-pivot.md`, актуальная архитектура — `../../memory.md`).

Полный контекст решения и обоснование — в одобренном плане сессии
(`memory.md` содержит выжимку архитектурных решений). Кратко:

1. MongoDB+Express+JWT заменён на Firestore + Firebase Auth (Google-only) — пользователь
   предпочёл встроенную offline-синхронизацию Firestore вместо самодельного sync-слоя для
   мобильного клиента.
2. Мультитенантность — общая Firestore-база, `tenantId` в документах, изоляция через
   Security Rules + custom claims (не отдельная БД на клиента — слишком тяжело для этого масштаба).
3. Мобильный клиент — Expo/React Native в том же монорепо, с пакетом `shared/` для переиспользования
   бизнес-логики (hooks, repositories, валидация) между web и mobile.
4. Модель данных — единый журнал транзакций (не раздельные приход/расход), денормализованный
   баланс кошелька, пересчитываемый Cloud Function-триггером.
5. Меню/UX — дашборд как основной экран с drill-down в детальные отчёты, плюс разделы:
   Журнал операций, Кошельки, Категории, Отчёты, Настройки (+ будущие: Бюджеты, Регулярные операции).
