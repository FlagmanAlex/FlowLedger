# План: применение дизайна из `design_handoff_mobile_app` к WEB

## Контекст
В `.claude/plans/design_handoff_mobile_app/` лежит handoff тёмного неоморфного дизайна —
изначально нацелен на `mobile/` (Expo), но `client/` (web) сейчас полностью неоформленный (голый
`h1`/`ul`/`li`, дефолтный светлый CSS от Vite-скаффолда, который нигде толком не используется).
Экраны в спеке — Login, Dashboard, Journal (=Transactions), Add Transaction sheet. По решению
пользователя (2026-08-31) — сначала переносим на web, mobile откладывается (см. tasks.md).

Дизайн-токены и точные размеры/цвета — см. `design_handoff_mobile_app/README.md` (раздел «Design
Tokens» и по экранам). План ниже про то, как это лечь на web-архитектуру, которой в спеке нет
(спека — только мобильный портрет 402px, bottom-tabs, bottom-sheet).

## Адаптации под web (то, чего нет в спеке)
1. **Layout** — вместо мобильных bottom-tabs: боковой сайдбар-нав (те же неоморфные токены,
   raised-поверхность) на широких экранах; контентная колонка по центру, max-width ~640px (тот же
   ритм карточек, что и в мобильном спеке, не растягиваем на всю ширину). На узких — сайдбар
   сворачивается в верхнюю панель.
2. **Add Transaction** — модальное окно по центру (не bottom-sheet: это мобильный паттерн).
   Сегменты/кошельки-чипы/сетка категорий — как в спеке. Числовую keypad-сетку не переносим —
   это костыль под touch-only ввод, на web есть обычная клавиатура: используем стилизованный
   `<input type="number">` в том же неоморфном инпуте (явное отклонение от «high-fidelity»,
   осознанное).
3. **Экраны вне спеки** — Wallets, Categories, Reports, Settings в handoff не описаны (там только
   Login/Dashboard/Journal/Add). Стилизуем тем же набором примитивов и токенов (карточки, списки,
   чипы, прогресс-бары), не придумывая новый язык — экстраполяция, а не своя стилистика.
4. **Reports** — использует уже установленный `recharts` (сейчас не используется, зависимость уже
   в `client/package.json`) для тренда по месяцам, стилизованный под токены; компактный bar-chart
   из спеки Dashboard остаётся там же как есть (маленький виджет, не полноценный график).

## Технический подход
- `client/src/styles/tokens.css` — цвета/тени/радиусы/типографика как CSS custom properties (1:1
  из README «Design Tokens»).
- `client/src/styles/primitives.css` — переиспользуемые классы: `.neo-card`, `.neo-raised`,
  `.neo-inset`, `.neo-button`, `.neo-input`, `.segmented`, `.chip`, `.icon-circle`,
  `.progress-track`/`.progress-fill`, `.list-row`.
- `index.css` переписывается полностью (сейчас — светлая тема дефолтного Vite-шаблона, нигде не
  задействованная по сути — экраны рендерят голый HTML без classNames). `App.css` и
  `assets/react.svg`/`vite.svg`/`hero.png` — не импортируются нигде, удаляются как мёртвый
  скаффолд.
- Логика экранов (react-query хуки, react-hook-form+Zod, router actions) не трогается — только
  JSX-разметка/className и мелкие презентационные подкомпоненты (`IconCircle`, `WalletChip`,
  `CategoryBar` и т.п.) в `client/src/components/ui/`.
- Форматирование сумм — общий хелпер (пробел между тысячами, запятая-разделитель, ₽) вместо
  разрозненных `toFixed(2)`, используется на всех экранах.

## Порядок реализации
1. Фундамент: `tokens.css` + `primitives.css`, переписать `index.css`, удалить мёртвый скаффолд.
2. `Login` — 1:1 по спеке.
3. `MainLayout` (нав) — сайдбар на токенах (свой лэйаут, не из спеки, но на тех же токенах).
4. `Dashboard` — 1:1 по спеке (баланс, кошельки, категории-бары, тренд, последние операции).
5. `Transactions` («Журнал») — сегменты-фильтр, группировка по дате, FAB → модалка Add Transaction.
6. `Wallets`, `Categories` — карточки/списки/чипы, экстраполяция токенов.
7. `Reports` — recharts-график + ранжированные списки категорий (переиспользуем `CategoryBar` с
   Dashboard).
8. `Settings` — карточка профиля + выход.

## Вне рамок этого плана
- Перенос того же дизайна в `mobile/` (Expo/RN) — отдельная задача, тот же токен-набор, но через
  RN `StyleSheet`/`NeoCard`-хелпер (см. README `design_handoff_mobile_app` — двойной shadow-layer
  для iOS/Android). Не начато, зафиксировано в `tasks.md`.
- Оплата/бюджеты/регулярные операции и прочие open TODO из `memory.md` — не относится к этому
  плану, это чисто UI-слой поверх существующей функциональности.
